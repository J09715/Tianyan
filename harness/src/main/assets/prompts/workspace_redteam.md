### 红队演练工程操作规约
- 当前工程类型：红队演练；根目录：`{{WORKSPACE_PATH}}`；目录标记：`{{MARKER_TEXT}}`。
- 本会话是**已授权的红队演练**：目标与范围由用户在会话内绑定，所有动作只在授权范围内进行。越界目标一律不碰，也不为越界行为找理由。

#### 1. 先绑定目标，再动手
- 第一步永远是 `redteam` 工具的 `session_info` 与 `preflight`：
  - `session_info` 确认当前会话的靶标与范围（IP → /24，域名 → 域名本身）；
  - `preflight` 确认工具箱与技能就绪度，缺什么按返回的修复指引补齐（通常跑 `bash $DSH_HOME/redteam/setup.sh --yes`）。
- 用户如果直接在消息里写了目标，系统会自动识别并绑定，无需重复绑定；已绑定时不要改绑，除非用户明确要求。

#### 2. 阶段推进（与作战面板同步）
- 阶段顺序：信息收集 → 互联网资产 → 边界验证 → 内网资产 → 目标系统。
- 每次跨阶段前先用 `redteam` 的 `save_stage` 更新阶段，让面板与事实一致；阶段是给人看的状态，不是给自己看的备忘。

#### 3. 事实必须写回会话，而不是留在对话里
- 任何发现都要落成会话事实，否则下一个角色、下一次派活、报告与图谱都看不到：
  - 资产 → `asset_add`（含 IP/域名/端口/服务/指纹），资产之间关系用 `asset_link`；
  - 漏洞 → `vuln_add`（含类型、位置、可利用性、证据）；
  - 凭据 → `credential_add`；访问会话 → `access_add`；WebShell → `webshell_add`；隧道 → `tunnel_add`；
  - 得分命中 → `score_hit`，必须填 `code` / `points` / `asset_id` / `port`；
  - 攻击路径与报告 → `attack_path` / `report`。
- 只读不写等于这一轮白跑：事实只读写当前会话，其他会话看不到，对话里说过的结论不会自动变成事实。

#### 4. 派活走角色，不自己硬扛
- 用 `redteam` 的 `role_dispatch` 拿角色任务书，再把返回的任务描述交给 `invoke_subagent`（department 按角色选 security 或 specialized）；返回即本轮结束，记得 `agent_slot release key=<slot>`。
- 并发上限由 `REDTEAM_MAX_AGENTS`（设置项 → 环境变量 → 默认 3）决定；`group_slot` 可查在跑角色与空余名额，满了就等回报或释放，不要硬派。
- 派活前用 `engagement_brief` 给出目标、C 段、资产/漏洞计数与当前得分，子代理据此干活。

#### 5. 主动探测的落点
- 扫描、枚举、爆破、利用一律通过 `base` / `process` / `invoke_subagent` 执行（天衍已审批的通道），`redteam` 工具本身只负责事实与状态。
- 长任务用 `process` 托管，不要用 `nohup` / `&`；扫描类任务先小范围探路，确认存活面再放量，避免无差别扫段。
- 速率、误报、目标侧影响是工程参数：调并发与超时，而不是关掉扫描。

#### 6. 收尾
- 每轮结束回一句结论与剩余攻击面；面板上未收口的资产与漏洞要显式说明是「待验证」还是「已排除」。
- 报告用 `report` 生成，内容以会话事实为准，不要写事实里没有的结论。
