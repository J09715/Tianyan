# 群聊按需分层：实施与验收

> 当前团队模板与审议机制见 [GROUP_TEAM_GOVERNANCE.md](GROUP_TEAM_GOVERNANCE.md)。下文记录最初的分层实施；现在派单也接受明确的审议协作授权，协作任务深度上限为八层，组织树仍为三层。

## 范围与默认行为

组织关系属于群聊。同一 Bot 在不同群可以有不同上级；群主控是根节点，未设置上级的成员默认直属主控。用户在「群信息 → 团队结构」中手动调整，最多三层，不自动创建组长或修改组织。

简单任务直接执行；复杂任务只有在下级能独立负责拆解、协调和验收时才继续委派。组织树规定授权，任务依赖与批次继续沿用现有执行机制。

## 实施步骤

1. **关系持久化**：成员记录保存可空的直属上级覆盖值。事务内校验成员归属、唯一上级、根节点、循环和深度。74 → 75 升级保留成员和历史任务，不触发执行；移出负责人后，其直属下级恢复直属主控。
2. **执行层权限**：群内新委派只允许直属下级，数据库事务再次核验。查看允许本人的任务及后代证据；续办和取消只允许原派发负责人。普通组长不能创建 Bot 或改组织。用户通过工作面板保留人工介入能力。
3. **任务生命周期**：保存原派发负责人及父任务，组织编辑不转移历史任务。组长异步派单后进入 WAITING_CHILDREN，子批次结束后以幂等续办要求回到原任务会话。组长验收并结束后才向更上层交付。取消父任务持久关闭后代并取消进程内执行；不确定执行不自动恢复。
4. **界面与上下文**：群信息提供团队结构编辑器，非法上级不出现在候选中，保存错误保留草稿。提示词和名册只列直属下级；强调必要背景、简短交付、产物引用和验证证据。初始历史、轮次历史和执行期复核共用按持久任务归属的过滤；任务面板区分等待下级与真实受阻。
5. **离线验证**：覆盖关系隔离、非法编辑原子性、跨级拒绝、原负责人保留、嵌套等待与原会话验收、父任务取消、迁移。运行数据库、Harness、Bot 界面回归、应用依赖图测试、架构门禁与 Debug APK 构建，不调用付费模型。

## 成本与边界

- 复用批次事件唤醒与现有有界群历史；不增加模型轮询，不因增加管理关系自动发起模型调用。
- 层级权限限制派单和任务控制，不是文件系统隔离。write_paths 继续是群内任务的建议范围，不能保证成员零冲突。
- 已实现可选的本地共享请求预算，默认 0（不限）；不提供供应商账户级费用硬上限、自动组织调整、任务负责人迁移或独立验收状态机。验收由原负责人在原任务会话完成，成员声明不等于已验收。
- 自动注入先按任务与批次的原始归属过滤，再使用原有历史窗口。独立任务只接收自身、直属子任务交付，以及面向自己或原上级的用户纠正；未指定成员的用户广播保留。公开普通群聊继续共享，独立任务仅采纳自身与原上级的普通发言。未知任务 ID 或模型正文冒称的“汇报对象”不能扩大范围。
- 同一 Bot 的不同独立任务按任务 ID 和原会话区分；组织调整不把旧任务资料自动转交新负责人。群界面仍可查看原始消息，过滤不清除旧会话中已保存的上下文，也不构成文件或工具访问隔离。
- inspect-assignment 提供当前任务及后代独立会话的已入账 token，重试和续办沿原会话累计；不计入任务树外的主控群会话。输入、输出、推理、缓存分别列示，不把推理或缓存再次相加；账本缺失明确标注，不能视为零消耗。只读取 SQL 聚合标量，不加载对话载荷或增加模型调用。
- 上述控制不承诺总 token 必然下降。预算闸门限制后续受控请求，不承诺实际账单绝不超限，也不回滚工具副作用。
- 调整关系前已受理的任务保持原负责人；移出负责人后，任务不能自动冒用新负责人续办，需用户核验与处理。

## 验收场景

主控 A、组长 B、开发 C、并列成员 D：默认全部直属 A；将 C 关联 B 后，A 只能给 B/D 派新任务，B 可以给 C 派单。A 能查看 C 的证据但不能直接续办或取消 C 的任务。B 的父任务等待 C，C 完成后 B 在原会话验收，最终 A 只收到 B 的交付。取消 B 的任务后，C 的迟到完成不能唤醒 B。

嵌套同步派单（wait=true、无批次）通过 awaitSynchronousTask 将下级结果直接返回组长原任务中的工具调用；不额外投递到组长的普通群会话。结果先形成原任务内的持久回执，同步工具拿到结果后，只确认相应任务版本和终态的待处理回执，避免重复启动模型。原等待已结束、进程退出，或随后使用 continue-assignment 补充要求时，未确认的回执回到原组长任务和原会话验收；仍有活动下级时保持等待。父任务若已中断或失败，仍由用户核验后显式恢复，不自动重放。子任务失败、中断或取消也保留真实结果，不因吞掉通知让父任务永久等待。异步批次继续以原有批次回执返回原任务。

父任务取消后，其后代不能单独新增续办要求；需先核验并显式恢复原上级任务。派单、续办受理和领取执行在事务内核对原任务祖先链，取消、缺失、循环或归属不一致的祖先链不能启动执行；幂等重试已有要求不重新打开任务。取消遍历穿过已失败或已结束的中间任务，关闭仍在排队、执行、等待下级或受阻的后代，保留中间节点的历史终态。迟到批次不能通过已取消的祖先重新唤醒原任务。

工作批次 ID 与来源群、负责人、来源会话和原轮次绑定；复用 ID 时四项必须一致，批次元数据还须匹配当前任务的群、原派发负责人及父任务会话。校验与插入在同一事务内完成，冲突拒绝不新增任务、会话、要求或预算，也不增加原批次 revision。合法的同源成员派单仍合并为一个批次和共享预算，全部结束后统一回报。

串行依赖在数据库派单事务中要求所有前置任务属于本群且为 COMPLETED。领取执行时再次校验；前置任务被重新打开、删除或依赖记录不可解析时，将本轮持久标记为受阻，不进入执行器、不调用模型。已有补充要求仍可持久受理，但不能绕过领取校验；核验依赖完成后由负责人继续原任务，不增加模型轮询或自动重放。

同步工具接收下级回执后，回执单独标为 received，记录“已接收、仍待原任务验收”，不混同 cancelled 或任务验收完成，也不产生新的原生轮次。中断父任务的旧待执行要求仍遵循原有恢复规则：人工继续前不从恢复队列重放；人工继续会关闭旧待执行要求，但已保存的下级交付正文仍留在原任务历史供核验。历史 cancelled 记录不推测为已接收、不回填。

## 第三阶段：本地共享预算

- **配置**：「群信息 → 任务预算」设置新委派默认额度，0 为不限；下方可调整已有批次额度。列表保留最近 30 个预算，并额外保留所有含待处理任务的旧预算（排队、执行、等待下级、受阻、失败或中断），避免老任务失去调额入口；已完成或取消的旧预算仍持久保存，再次续办时恢复可见。默认值只作用于新预算；修改现有额度不清零已结算、预留或未知消耗，不自动启动模型。模型工具没有修改预算接口。
- **归属**：同一轮批次中的根任务及其全部后代共享一个持久预算 ID。子任务与补充轮次继承它，换执行 Bot 或继续原会话不会获得新额度。任务树外主控群会话、另一轮独立工作不计入该批额度，这不是整个群或账户的总费用限制。
- **请求闸门**：在受控 OkHttp 网络拦截器中，按实际序列化 UTF-8 请求字节数加输出上限和 framing 余量预留；数据库事务检查余额并占额，防止并发重复花费。输出上限缺失时为启用预算的模型配置补默认上限；无法核对明确上限的请求拒绝。字节预留是保守策略，尤其图片可能使任务提前受阻。
- **重复请求**：凭据轮换、网络层重试与 Anthropic pause_turn 内部续跑逐次预留；成功的内部续跑用合并 usage 结算一次。非成功 HTTP、断线、取消、未完整回传 usage 的预留保留；重启不释放。成功返回后结算故障是本地核验问题，不能作为网络错误自动重发。
- **口径**：成功 usage 按输入加输出结算，Anthropic 额外计入其输入字段之外的缓存读写，不再次加 reasoning；账本统计与预算状态分别显示，压缩摘要和受控辅助请求也受预算约束。历史独立任务首次绑定补入已有会话账本，未入账或无法归因的历史不作推测。
- **受阻与恢复**：不足时拒绝新增分派或模型请求，把本轮保留为受阻并报告原负责人；不能宣称完成。用户核验产物、调整原预算后，从工作面板继续原任务。不会因提高额度而自动重放，不释放未知消耗来伪造余额。
- **边界**：只覆盖内置 Provider 路径以及使用注入 OkHttpClient 的适配器；Shell、自带网络客户端的第三方程序、供应商额外隐式用量不受此客户端闸门保证。实际 usage 超过预留时照实结算并阻止后续请求，不保证供应商最终费用绝不超过配置值。已保存的结果、审批、原会话与工具副作用沿既有恢复语义保留。

数据库 75 → 76 新增默认额度、预算归属与持久请求预留表，历史额度默认不限；迁移本身不发起执行、不重放、不产生计费记录。
