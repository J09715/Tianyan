# v2 插件补齐工作（2026-10-19）

本轮范围：权限与即时撤权、外部 PROCESS/MCP 工具、外部 Provider 和工作流节点。外部原生 IPC、后端替换与强进程隔离不属于本轮；PRoot 同 UID 边界保持不变。

## 执行方案

1. `FullAccessGrant` 只保存内存中的原生确认，绑定发行版、插件身份与包版本，限时 30 分钟。开发者模式仅为入口前提，关闭清空确认；签发凭据的准入回调每次复核同一授权代次，关闭再开启不能使旧凭据复活。
2. 安装收据决定外部扩展的运行清单，候选升级不能替换旧运行配置。只读元数据发现不启动进程；调用时再次检查安装版本、当前本地系统与执行环境，并持有安装/卸载互斥准入。
3. 包内声明受限的工具、Provider、工作流节点及 MCP 程序入口。宿主动态投影为现有 Harness 扩展，禁止覆盖内置身份。调用在审批之后才启动 MCP，沿用严格 Schema、输出脱敏、取消与恢复规则。
4. Provider 必须用独立插件命名空间显式选择，不能覆盖已有 Provider；默认不把宿主密钥仓储交给扩展。工作流仍经 `PLUGIN_ACTION` 的逐次原生确认；恢复不重放成功节点。
5. 模板增加可运行的离线 MCP 示例，覆盖三种扩展；不调用真实模型 API。补协议、调用链、图装配与完整端到端回归，再进行可用设备上的验收。
