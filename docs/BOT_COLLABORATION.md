# Bot 群聊协作与可靠分发

## 业务任务、阶段派单与执行停滞

用户发起的群聊轮次产生业务任务 ID，接力槽位、原生排队任务、方案、独立任务、后续要求及结果回执沿用该归属。原生 operation/batch ID 仍代表一次运行或派发批次，不充当整个业务任务的 ID。业务归属由程序在原生受理前写入；不从模型正文、角色名字或工作区路径推断。普通新用户消息开启新轮次；修改已委派任务使用 `continue-assignment`，保留原任务及会话。

同群、同业务任务、同阶段、同 `work_item_id` 在数据库事务中只创建一次，重复派单返回原任务、状态及原负责人，不新建会话或覆盖指令。首次派单确定本阶段的派单负责人，其他成员不能另起该阶段工作项。工作项缺省按执行成员去重；同一方案的独立模块可提供不同稳定 ID，由原负责人并行分配不冲突的交付物、写入范围和验收标准。不同方案版本、执行负责人下发的交付阶段有独立阶段标识。已取消或受阻的原工作项也不会因重试自动重建，须核验后续办。

每次成功派单（含复用原任务）保存原生 operation 的派单回执。Bot 在该次群聊发言中 @ 已派成员时，不再追加普通接力执行；没有派单回执的讨论 @ 和用户显式点名的槽位仍正常处理。异步回报沿原负责人及原业务任务返回。新业务任务的各独立阶段共享预算归属，普通群会话的模型请求仍不计入独立任务预算，不能据此声称整个群聊消耗都受到额度限制。

独立任务另设有效执行进展计时，与 HTTP/SSE 活动、模型正文/推理及工具入参输出分开。默认 2 分钟无已完成工具步骤时发程序预警，5 分钟仍无进展则停止本轮；推理、心跳、输出截断后重生成不刷新这一时限。工具运行及审批等待暂停此计时，沿用各自超时；工具结果产生后重新计时。停止前重新核对原生任务和工具步骤，发布进度期间刚完成的任务、审批变化及新工具优先处理，避免用旧快照误判超时。每个模型响应的输出上限恢复最多一次，继续占用原预算。停止后核验原生工具记录：确定没有未知副作用时记为 BLOCKED，否则记为 INTERRUPTED，保留原会话、产物和原负责人的回报，不自动另开任务。诊断中的到期观测不等于最终受阻状态，最终结果以持久交付和任务状态为准。

阈值由持久化的 `GroupChat.executionLimits` 配置，目前没有单独的界面编辑入口。诊断导出包含业务任务、阶段、工作项、原负责人、请求开始时间/次数/重试原因，以及最后传输活动、模型输出和有效执行进展时间；缺失信息不推测。数据库 82 → 83 只增加关联、回执及观测字段；历史任务不补猜业务归属，也不自动重跑。离线回归覆盖并发派单、独立工作项、@ 公告、排队归属、方案流转、进展超时与未知副作用。

## 团队模板与审议制衡

市场支持一次导入独立团队组（成员、上下级、审议规则），内置三省六部与软件交付模板。组织在团队创作界面统一编辑，连线架构图展示直属、送审、准奏与封驳。群聊引用团队，团队先保存草稿并发布，群聊显式升级到不可变版本；繁忙群保持旧版，审核记录与执行批准按群和团队版本隔离。详见 [GROUP_TEAM_GOVERNANCE.md](GROUP_TEAM_GOVERNANCE.md)。

## 按需分层团队

团队组中可关联直属上级，默认全部直属团队主控，最多八层。循环、非团队成员及超深结构在保存事务中拒绝；群信息展示只读架构与团队引用。早期分层实施背景见 [GROUP_TEAM_PLAN.md](GROUP_TEAM_PLAN.md)，当前配置所有权以团队组文档为准。

群内派单在工具层与数据库事务校验直属关系或明确配置的审议协作授权。负责人可以查看后代任务证据，续办或取消只允许原派发负责人；用户仍可通过工作面板介入。已有任务固定原负责人，调整组织不转移任务控制。父任务记录原始关联，异步派出子任务后进入「等待下级交付」，子批次结果幂等进入父任务的原会话供验收，再向上汇报；取消父任务会关闭后代，迟到结果不能复活执行。

数据库 74 → 75 增加成员直属上级与任务父关联；历史成员保持默认扁平结构，历史任务不推断父关系、不触发执行。分层提示展示直属及明确授权的协作名册，沿用有界历史和批次通知。

初始请求、群聊轮次与执行期复核按持久任务/批次归属选择自动注入的消息。独立任务保留自身、直属子任务交付及相关用户纠正，同 Bot 的其它独立任务和其它分支不自动注入；公开群聊发言仍共享给群聊轮次，未指向特定成员的用户广播仍保留。过滤先于条数窗口，无关分支噪声不消耗最终复核次数；组织调整不改旧任务归属。群界面原消息与会话中此前已保存的上下文不会被清除，过滤不是工具/文件权限边界。

inspect-assignment 可查看当前任务与后代独立会话的已入账 token。查询沿原始父任务关联汇总持久账本标量，续办/重试累计，缺失计量明确标注；推理与缓存独立列示，不重复相加。统计不包括树外主控群会话，也不是费用结算或全局硬预算，不承诺总消耗下降。

「群信息 → 任务预算」可为新委派设置共享额度并调整已有批次，默认 0 不限。同一轮根任务及其后代共用额度；受控模型请求在 HTTP 发送前按请求字节与输出上限原子预留，重试和协议内部续跑不免费。未知请求不释放预留，重启不重置；真实 usage 结算，预算不足保留受阻状态，用户调整后继续原任务。模型不能修改预算，修改额度也不自动重放。75 → 76 迁移只建立元数据。具体口径及第三方直连、历史未入账、实际费用等限制见 [GROUP_TEAM_PLAN.md](GROUP_TEAM_PLAN.md)。

## 已实现：持久收件与委派回报

群消息内容仍只由 `group_messages` 持有。`group_deliveries` 记录来源消息、目标 Bot、处理状态及原生受理后的 session/task ID，不复制提示词或附件载荷。

- 用户消息与顺序轮次在同一 Room 事务中保存；委派报告等可靠分发入口仍使用收件记录，同一来源与 Bot 只有一份回执。
- 后台委派创建时固定 `reportToBotId`。任务终态、确定 ID 的群内结果报告、主控收件在同一事务中提交。重复终态回调不覆盖先前结论，也不重复唤醒主控。取消仅保留报告，不唤醒主控。
- 收件处理沿用 `(Bot, Group)` 的执行锁，与普通群回复、定时回复共享停止边界；独立委派按任务 ID 串行。在实际处理时重新读取群记录；这不保证同时运行的其他成员已经看到彼此尚未提交的回复。
- 来源附件在处理时经现有 SAF 授权和大小检查读取，不把图片编码复制到收件表。
- 移出成员会取消该成员的未结束收件；重新加入不会复活它们。清空消息、解散群聊通过来源消息的外键级联清理回执。
- 群聊诊断导出展示最近 100 份回执，包含来源、状态、Bot、session/task 引用及安全错误说明。

## 群聊轮次的执行与恢复

- 用户任务正文和准备后的附件说明完整保存到轮次；历史摘要的截断不截断本次任务。附件必须先完成复制、大小检查与图片编码，再原子保存用户消息及可恢复轮次。附件准备失败只保留用户消息和错误通知，不创建可执行轮次。
- 轮次创建与发言前的 `SPEAKING` 检查点必须成功提交，存储失败立即停止执行。已开始发言但未提交完成状态的槽位在重启后标记失败，不重新提交任务；取消或清除后的轮次不能被迟到进度重新激活。
- 群回复跟随原生受理回执中的 task ID；排队时间不消耗该任务的首输出预算，不用同一会话前驱或后继的运行状态判定完成。任务完成后严格读取其持久化交付记录，以该记录引用的正文和工具结果落定群气泡。
- 迟到回复保存同一个 task ID（数据库 71 → 72），重启时先准备会话并读取持久化历史，再恢复观察。旧记录缺少 task ID 时保留兼容观察和结果待核对语义；历史读取失败不当成空历史继续执行。

## 重启与停止语义

| 状态 | 重启处理 |
| --- | --- |
| `pending` | 尚未提交原生执行；重查来源和成员后继续分发 |
| `submitting` | 原生受理可能已成功；标为 `unknown`，不再次提交 |
| `admitted` | 保留原生 session/task 引用，标为 `unknown`，不再次提交 |
| `completed` / `failed` / `rejected` / `cancelled` / `unknown` | 不自动重放 |

不确定结果在群内留下“待核对”提示，已保存的流式正文、推理和工具步骤保留。用户停止群聊会先取消持久收件，再排空进程内回复队列，后续新消息仍可发送。

启动先沿 Harness 原有策略恢复原生任务，再核对遗留委派并启动群消息收件和轮次恢复。首次发送也可初始化收件处理器，初始化具有进程内互斥与幂等保护。原生执行归 Harness 管理；已持久化的迟到回复按 task ID 恢复观察，普通中断收件仍按上表标记待核对，不重新提交执行。用户可通过原会话和诊断回执核验。

SQLite 与 Harness 原生受理之间不共享事务，因此不宣称 exactly-once。存储故障与受理途中异常采用保守待核对语义；不会为了补发一条群回复而重跑可能已经产生副作用的工具。

历史消息在数据库 61 → 62 升级时保留，但不会补建收件并触发执行。旧委派的报告接收人默认为空，不推测其历史请求者。

## 默认自主执行

默认工具权限为 `FULL_ACCESS`，不依赖用户在消息中额外写授权指令；新会话、Web 会话和便携导入均采用该默认值。61 → 62 升级将既有全局设置及会话切换为完全访问。用户之后显式选择其他模式时仍按选择执行；Android 系统权限与凭据可用性不由此虚构或绕过。

`ask_user` 最多等待 60 秒；到期原子认领请求，采用 `recommended=true` 的选项，其次为标有推荐的选项、第一选项。自由输入问题可指定 `default_answer`，未提供时告诉模型基于已有事实自行决定，不编造缺失信息。结果明确标注这是自动默认值，非用户确认，再沿原任务恢复。后台子智能体不建立等待请求，直接采用推荐项。超时不等于自动批准普通工具审批；请求参数、工作区和运行归属校验仍有效，停止或更换运行后旧回调不得恢复任务。

## 已实现：独立任务与原会话续办

群内 `assign-task` 为每个任务创建独立原生会话，保存来源工作区、执行环境和模型快照。同一 Bot 可以承担不同任务；同一任务的要求按持久队列串行执行，不打断当前工具。每轮完成后保存自己的报告并回报创建任务的主控，保持原任务 ID 和会话历史。

- 工作面板提供“补充要求 / 继续任务”，主控也可以调用 `continue-assignment`。重复提交同一个 `request_id` 不会增加轮次；不同内容必须使用不同 ID。
- 状态区分排队、运行、受阻、结果待核对和完成。`report-assignment` 只允许实际任务会话记录自己的受阻原因与产物路径；这些是成员声明，不能代替验收，也不能提前宣布本轮执行完成。偏好问题仍采用 60 秒推荐项规则。
- 运行中补充的要求在当前轮次结束后执行；中断后显式续办会取消尚未执行的旧要求，再执行新要求。结果不确定时应先核验已有产物。
- 取消先持久关闭当前及排队要求，再停止执行，迟到结果不能覆盖取消状态。清空或删除群聊同时清理独立任务会话。
- 重启将提交中和已受理但未结算的轮次标为结果待核对，不自动重新提交。原生恢复仍由 Harness 管理；原会话正在运行或已经删除时拒绝另起会话冒充续办。
- 群聊诊断导出包含独立任务的轮次、受阻原因、产物声明及原会话记录。

数据库 62 → 63 为新任务增加独立会话标记与轮次表。历史委派保留原记录，不把曾经共享的群会话推断成独立任务，不自动迁移执行。

## 成员模型、工作区与超时诊断

每位成员可在详情中选择任意已添加的供应商档案及其具体模型。配置属于成员，应用于其私聊、所有群会话与独立任务，不提供单个群的覆盖。成员始终可以调用 `bot-management.list-models` 查看目录；仅当用户在成员详情中开启「允许成员自行切换模型」后，才可以调用 `select-model`。新成员与升级后的旧成员默认关闭该权限，旧配置保留。权限在成员锁内重新读取并校验，工具不能自行解锁。模型目录支持供应商与具体模型分页，避免长目录截断后无法继续查看。工具身份由会话映射确定，不接受目标成员参数；目录只返回档案 ID、名称、供应商和模型名，不返回凭据。切换同步当前成员的私聊、群会话与独立任务，在下一次模型请求生效，不修改其他成员或全局激活模型。

数据库 63 → 64 增加可空的 `persona_bots.modelVariant`，原成员保留档案绑定并使用档案默认模型；72 → 73 增加默认关闭的 `allowModelSelection`。归档携带具体模型与自助切换权限，旧归档导入默认锁定。新任务采用成员自己的档案与具体模型；未绑定档案时，普通发言、私聊和独立任务统一跟随全局默认，不继承派单者的模型。旧任务续办与已有普通会话发言前会纠正偏离成员配置的绑定，保留原工作区与执行目标。绑定档案被删除或具体模型被移除时明确报错，不静默切换到其他供应商。

Bot 发言前保留已绑定的工作区和执行目标，不因会话空闲而重新选择发行版或服务器。独立任务继续复制来源的原始工作区身份（包括空值），派单前按有效工作区校验建议写入路径；新项目使用工作区内路径，拒绝 `/root`、跨项目路径和 `..`。群聊任务的 `write_paths` 是建议范围，不宣称提供 Shell 隔离。

回复观察通过独立的输出活动序号跟踪正文、推理和所有工具参数分片，不以界面状态文案或 SSE 心跳作为输出证据；原有消息与工具投影也参与核验。回复观察只把实际正文、推理或工具参数视为模型输出，空助手占位不会解除首次输出期限。首次输出和模型阶段连续无新输出均允许等待 10 分钟，与底层隐藏推理流等待上限一致；工具执行中及审批等待不适用模型无输出期限，整轮允许 60 分钟（审批等待不计入），不再因跨过十五分钟而停止仍活跃的任务。停止文案与观察器共用时限配置。底层连接/读取错误和服务端自身超时仍会提前结束请求。停止请求不等于底层资源已经退出；超时和中断保留 `unknown` / 结果待核对状态，不自动重放。原生失败或取消后的早期进度文字不会被认定为完成结果。

任务通知监听全部会话的运行状态，不依赖当前聊天页；普通聊天、成员群会话和独立任务均纳入。通知按会话稳定标记，分别显示执行阶段、工具已完成/已发起数量、当前工具和已用时；这些是执行观察，不是目标完成百分比，不复制工具结果或模型正文。动作描述沿用会话状态，可能包含命令、路径等参数摘要，锁屏默认隐藏通知内容。等待审批期间保留常驻通知，完成、失败和停止显示不同终态；任务并行结束不覆盖其他会话通知。启动保留短暂受理宽限，避免服务先于运行状态就绪而退出。用户在系统授予通知权限并返回应用后，会重新尝试展示仍活跃的任务；系统禁用通知或渠道时应用不能强制显示。

群历史去掉已由同一任务结果报告覆盖的成员答复，保留较新的续办答复；预算优先保留较新消息。提示明确成员的准确 `bot_name`、异步派单后等待通知、正文与运行验收要求，以及真实审议与简化流程的区别。角色设定本身不构成审议门禁；用户配置的审议规则由数据库及工具入口强制执行。

诊断成员区分别列出群会话与独立任务会话；未加载运行态不再写成 `IDLE`。任务会话的运行事件、活动操作及日志纳入导出，群气泡时间明确标为创建／开始输出时间，结束时间以委派记录为准。

## 已实现：回复前复核群消息

普通群回复、定时回复和独立任务在原生受理前绑定来源群、执行 Bot 与本次占位消息。绑定时重新读取群历史，排队期间的用户纠正不会被旧快照覆盖；来源消息明确标为本次受理对象，不再冒称“最新消息”。

- 每次原生模型请求前检查群记录；准备结束一轮纯文本回复时再检查一次。出现新资料时，在同一次原生运行中持久加入带来源的上下文，再让模型修正结论，不重新提交整段任务或重放已完成的工具批次。
- 只采纳已落定的群消息，排除本次回复占位及普通系统噪音；成员仍在流式输出的半句话不会触发复核。消息内容或附件变化也会重新进入上下文，推理、表情等变化不会触发重复处理。
- 最多自动延长三次最终回复，持续同伴聊天不会无限延长运行。常规模型轮次仍受原有预算约束；没有新消息时不增加模型调用。不轮询群记录，不因为更新而中断正在执行的工具。
- 更新保留发送者类型和消息 ID，用户纠正优先展示，正文、条数与历史窗口均有限额；截断和省略会明确标注。新附件仅列名称，不声称已经读取正文。资料不会授予额外工具权限。
- 绑定只对实际执行会话有效；私聊及其他群不会借用当前群资料，移出成员后不再注入新消息。绑定结束后，迟到的更新由正常收件和后续任务处理；进程恢复仍遵循结果待核对策略。
- 群气泡等到整个原生运行结束才落定，中间已持久化的文本仍是草稿，可被后续复核修正。最终检查与新消息写入之间仍可能有竞争窗口，不承诺所有并发消息一定被当前回复看到。

独立新请求仍保留自己的持久收件，不因被当前任务看到就冒称已经处理；提示要求只修正当前结论、引用已验证产物，并避免重复执行和重复汇报。

## 已实现：记忆正文编辑、提交差异与可追溯恢复

Bot 详情页的记忆文件可点击阅读与编辑 Markdown 正文；提交可查看与第一父提交比较的统一差异，首个提交展示新增文件。正文编辑读取完整 UTF-8 文件，最大 1 MiB，超限或非法编码拒绝编辑，不把工具预览的截断内容当完整原文保存。

- 手动保存携带打开文件时的内容版本，在同一 Bot 记忆锁内核对。后台执行修改了同一文件时，旧草稿不会覆盖新内容，错误在编辑器显示；草稿保留，可复制合并或明确放弃后重新载入。
- 每次保存只提交目标文件，不顺带提交其他记忆草稿。大文本保存在详情页 ViewModel 中，旋转后沿用原版本；不把正文塞进 Activity 状态包。关闭编辑器或进程退出后，尚未提交的草稿不保证保留。
- 差异预览最多 64 KiB，超限明确显示提示，不修改存储内容。差异读取和恢复只接受当前历史可达的提交，不接受任意 Git 修订表达式。
- 恢复前先把当前工作文件（含未提交、新建及忽略文件）写成可达的备份提交，再应用目标内容并生成恢复提交；不移动到旧 HEAD、不删旧历史。恢复前快照就在时间轴中，可以再次恢复。
- 恢复先验证路径、文件类型与大小，拒绝符号链接和 Git 元数据路径。为控制手机资源，单文件不超过 1 MiB、总内容不超过 16 MiB、最多 256 个文件。恢复是逐文件替换；若文件系统操作中途失败，已提交的恢复前快照仍保留，可据此再次恢复。

## 群聊阅读与任务摘要

成员候选只在光标位于独立的 `@` 词元中时出现，按成员名称和职责筛选；选择后替换当前词元并保留后文。任务摘要按任务 ID 合并持久记录、实时执行与流式气泡，同一成员的不同独立任务分别计数；显示执行中、排队中和待处理数量，点击打开现有工作面板。终态任务不被迟到的实时投影重新算作运行中。

成员卡片展示供应商档案名称与具体模型，配置失效时明确提示。完成后的长回复和系统报告默认显示最多八行的纯文本预览，可展开阅读原始 Markdown；流式输出与短消息不折叠，历史消息正文不变。群聊气泡不再显示表情反应和更多按钮。

成员回复按思考过程、工具调用、正文的顺序呈现。工具调用独立成框，默认折叠，显示调用数量与执行状态；少量调用也可展开或收起，展开列表限制高度并支持滚动，状态按消息保存。正文不随工具框折叠，没有正文时不额外生成空气泡。已停止消息中尚未收到结果的工具显示待核对，不继续冒充执行中。

普通群回复与迟到回复的实时正文先发布到内存，不等待恢复检查点落库。检查点由独立 IO 协程串行保存，最多保留一个待写的最新草稿，继续使用两秒写入间隔；观察结束、取消或移交后台观察器前排空或取消并等待写入协程退出，避免旧草稿覆盖最终状态。写入失败仍会终止该观察并沿原有失败路径收尾，不静默忽略持久化错误。模型正文快照继续按 16ms 发布，不限制 SSE 接收。

正文从 `StreamBuffer`、会话消息投影、群回复观察器到群气泡使用不可变 `ChunkedText` 快照，封存块按 2,048 个 UTF-16 字符共享，只复制活动尾块。完整字符串仅在检查点、最终提交或兼容接口读取时按需拼接；历史记录直接复用已存在的字符串。助手的 `text`、群消息的 `content` 在 JSON 中仍为字符串，不新增数据库迁移。推理正文仍沿原有字符串接口发布。

流式 Markdown 使用共享块解析器，逐次只扫描新增源文本；代码围栏以外的空行结束后固化前面的解析块，后续只重新解析未完成尾部，并保留已固化块的对象供 Compose 复用。代码块内的空行不会误切块，表格和列表在边界前可继续增长。正文替换、变短或恢复为另一份快照时清空增量状态；结束后仍用完整正文渲染。该优化不改变已有 Markdown 语法，也不承诺把一个未结束的超长段落或代码块拆成多个独立块。
