# 像素办公室场景数据

`feature/bot` 的 `OfficeSceneSpec` 是工位、座位行为、互动对象、区域牌、楼层、固定家具足迹、
看板和环境锚点的共同入口。默认实例清单在 `OfficeSceneDefaults.kt`；纯数据类型在 `OfficeSceneSpec.kt`。

## 新增和移动对象

- 新增工位：在 `defaultOfficeDesks()` 增加一个 `OfficeDeskSpec`，提供唯一 ID、位置和动画相位。
  底图、细节、人物座位、屏幕动画和可选阴影均由实例派生，无需修改 renderer 或分配策略。
  清单顺序决定工位分配优先级；动画相位独立于清单顺序。
- 移动工位：修改实例的 `x/y`。屏幕、座位、抽屉装饰和阴影均使用局部偏移。
  现有右侧工位保留原图的装饰差异，`drawers/shadow` 描述这些差异。
- 新增猫：在 `defaultOfficeCats()` 增加 `OfficeCatSpec`，指定 `SLEEPING/PERCHED` 风格。
  图像、尾巴动画、点击区和抚摸爱心共用实例坐标。ID 同时作为 Compose 测试标签和互动状态键。
- 新增咖啡机：在场景的 `coffeeMachines` 清单增加实例，指定不同 ID。
  机身、指示灯、蒸汽、点击区和冲泡反馈自动接入。
- 调整区域牌：修改 `defaultOfficeZones()` 中的锚点。文案资源和图标由 `kind` 决定。
- 调整其他座位：修改 `defaultOfficeSeats()`。`group` 决定分配池，`poses` 声明可用姿势，
  `roamOffset` 指定相对闲逛目标，`idleAction` 指定固定空闲动作。行为不依赖 ID 前缀或绝对坐标。
- 调整楼层：修改 `defaultOfficeFloors()` 的房间坐标区间。楼层决定工位交接是否同层，
  `floorAtRoomY()` 用于房间坐标校验，`floorAtSceneY()` 用于走道压缩后的角色坐标。
- 调整看板：修改 `OfficeBoardsSpec` 的任务板/目标板 bounds。位置、尺寸和背景像素密度随之变化。
- 调整环境锚点：修改 `OfficeAmbientSpec` 的水冷、会议屏、服务器灯、窗户灯点/云、灯和时钟锚点。
  粒子与时钟跟随实例，固定家具美术仍由房间 painter 绘制。
- 调整固定家具足迹：修改 `defaultOfficeFurniture()`。足迹用于楼层覆盖和障碍占用校验；
  `blocksWalking` 标记是否会阻止闲逛/溢出落点。家具美术尚未由实例驱动，移动美术时需同步修改 painter。
- 调整通道路径：修改 `defaultOfficeWaypoints()` 的房间坐标和 `links`。路径点用于角色换座和
  工位交接；`links` 按无向边处理，跨楼层默认经左侧楼梯连线。起终点到最近路径点之间
  使用楼层内栅格 A*，家具足迹作为软障碍参与绕行。

## 坐标与验证

实例使用原始房间坐标（192 × 448）。静态绘图按 3 倍像素生成，随后由 `PixelOfficeScene`
裁去空走道；Compose 在展示边界调用同一个 `y()` 转换，再应用相机平移与缩放。
不要将已转换的坐标写回实例。

`GroupCyberStudio` 将同一份场景传给座位分配与 `GroupPixelOffice`。
替换场景时重新分配人物、生成静态图并更新热点和牌匾；角色精灵生成保持独立。

场景构造时校验重复/空 ID、重叠座位、座位/屏幕/闲逛目标越界、热点越界与热点重叠。
热点重叠使用走道压缩后的坐标，匹配 Compose 实际命中范围。新增校验覆盖楼层区间/重叠、
座位与闲逛目标的楼层归属、溢出落点是否压在会阻挡行走的家具上，以及看板/环境锚点越界、
窗户灯点越出窗户。路径点还会校验越界、自链接、缺失目标和整图连通性；楼层同时校验压缩后高度
不变为 0、楼层顺序不重叠，以及锚点压缩前后仍属于同一楼层。当前仍允许美术边缘裁切；
寻路主干是稀疏 waypoint 图，端点短腿用 4 单位栅格 A* 和软障碍绕行；障碍代价不是硬碰撞，
窄通道仍可能贴边，装饰物遮挡暂不参与判断；固定家具足迹只做矩形占用判断。

## 当前边界

工位、猫、咖啡机、全部座位、五块区域牌、楼层、任务板/目标板、环境锚点、固定家具足迹和
通道路径点已经数据化。房间壳、沙发/会议桌/吧台等固定家具的美术及其装饰仍由现有绘图代码放置；
修改这些固定家具时，需要同时调整 painter、足迹、路径点和相关座位。角色换座与工位交接会
比较局部 A* 与 waypoint 主干代价，同层取较短路径；端点用软障碍绕开家具，跨楼层路径依赖左侧楼梯连线。

Canvas、Compose 覆盖层与程序化角色生成继续沿用。此阶段不引入图集导出、场景编辑器或热重载。
调试构建的相机控件会多出一个路径按钮，叠加显示楼层带、阻挡家具足迹、waypoint 和连边；
发布构建不显示该入口。
